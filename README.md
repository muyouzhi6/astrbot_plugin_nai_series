# Nai系列生图

给 AstrBot 使用的 NAI 4.5 / NAI 5 生图插件. 两套模型拥有独立的画师串、负面词、默认预设和生成参数, 可以在同一个会话交替使用. 支持批量并发后台生图, 完成后按原有人格继续对话.

## 开始使用

1. 在 AstrBot 插件管理中通过仓库地址或 ZIP 安装. 要求 AstrBot >= 4.28.1, Python >= 3.12.
2. 在插件配置中填写图片连接地址和密钥. 只需地址和密钥, 无需选择服务商品牌或接口模式.
3. 按需填写翻译接口地址、密钥、模型. 已有英文标签可在指令末尾添加 `--raw` 跳过翻译.
4. 在可视化预设列表中分别添加 NAI 4.5 和 NAI 5 预设, 填写预设名称、画师串、负面词. 将对应名称填入两套默认预设.
5. 发送 `/nai4 描述` 或 `/nai5 描述`.

支持配置多个连接. 根据地址自动识别 OpenAI Images 和官方图片协议. 当前版本只在接口明确拒绝认证、权限或路由不存在时尝试下一连接; 超时、服务器错误和下载失败不会自动重新提交付费任务.

常见地址:

```text
https://meinianda.top/v1
https://love.auroralove.cc/api/v1
https://image.novelai.net
```

美年达站点参考价格: NAI 4.5 为 0.013/张, NAI 5 为 0.13/张. 价格与计价单位以站点实时说明为准.

## 指令

| 指令 | 功能 |
| --- | --- |
| `/nai4 描述 --count 3` | 使用 nai4 模型配置批量生成 3 张, 默认 `nai-diffusion-4-5-full` |
| `/nai5 描述 --count 3` | 使用 nai5 模型配置批量生成 3 张, 默认 `nai-diffusion-5-full` |
| `/3nai4 描述` | 使用 NAI 4.5 批量生成 3 张 |
| `/3nai5 描述` | 使用 NAI 5 批量生成 3 张 |
| `/预设 nai5 风格名` | 切换当前用户在当前会话的 NAI 5 预设 |
| `/预设nai4 风格名` | 切换 NAI 4.5 预设, 支持无空格指令别名 |
| `/预设 nai4 none` | 本会话停用画师预设, 使用该模型默认负面词 |
| `/nai预设` | 将各预设及已绑定展示图绘制成图册, 不调用生图 API |
| `/nai预设 nai5 2` | 只看 NAI 5 预设的第 2 页, 每页 6 张卡片 |
| `/nai预设展示 nai5 风格名` + 图片或引用图片 | 绑定/覆盖预设展示图, 仅管理员 |
| `/nai预设试画 nai5 风格名` | 用该预设的样图描述付费生成一张, 自动保存为展示图, 仅管理员 |
| `/nai模型 完整模型名` | 设置 `/nai生图` 使用的模型 |
| `/nai生图 描述` | 使用当前用户在当前会话选择的模型 |
| `/nai状态` | 查看两套模型、预设、尺寸、步数和负面词长度 |
| `/nai重绘` | 用上一次实际提交的完整 prompt 和参数重新随机生成, 不重新翻译 |
| `/nai参数` | 查看自己上次实际提交的模型、尺寸、步数、正向和负面词 |
| `/nai取消` | 取消本地等待; 已提交上游的任务可能继续生成和计费 |
| `/nai取消 任务编号` | 只取消自己的指定任务 |
| `/nai任务` | 查看自己在当前会话的最近 8 个任务 |
| `/nai取图 任务编号` | 重新发送已保存的图片, 不重新生图 |
| `/nai帮助` | 查看指令与参数 |

指令前缀遵循 AstrBot 配置. 若你的唤醒前缀为 `.` 则使用 `.nai5 描述`.

### 单次参数

把选项放在描述后, 不会改动默认配置:

```text
/nai5 一只橘猫坐在窗边 --count 3 --preset 电影感 --size 832x1216 --steps 28 --scale 5
/3nai5 一只橘猫坐在窗边 --preset 电影感 --size 832x1216
/nai4 1.5::watercolor::, a cat --raw
/nai4 一只橘猫 --model nai-diffusion-4-5-curated
```

`--model` 不允许将 `/nai4` 改成 NAI 5, 也不允许将 `/nai5` 改成 NAI 4.5. 这两条指令的完整模型名也可以分别在后台改成所属模型族的 Curated 版本. 任意其他模型使用 `/nai模型` 和 `/nai生图`.
数字前缀与 `--count` 共用同一上限, 不要在同一条指令重复指定数量. 指令生图只发图, 不触发 bot 继续聊天, 也不把指令任务注入 bot 的任务上下文.

## 预设和状态

- 每个预设包含画师串和负面词. 预设所属模型族决定能在哪条指令使用, 不覆盖实际模型名.
- 预设负面词为空表示明确使用空负面词; 停用预设后使用模型的默认负面词.
- 同名预设可分别存在于 nai4 和 nai5. 绑定展示图时遇到重名须明确模型族.
- 每次生图读取最新预设文字. 排队中的请求使用提交时的快照, 防止执行中更换预设影响其他任务.
- 设置按用户 + 会话保存, 不会因群友切换预设串到自己, 重载和重启后仍保留.
- 预设可重命名而不丢失展示图. 删除已选预设后需要重新选择.
- 展示图、会话状态和上次参数保存在 `data/plugin_data/astrbot_plugin_nai_series/`, 更新插件不会覆盖.
- 图册依赖系统中文字体. Linux 可安装 Noto Sans CJK 或文泉驿, 也可指定 `gallery_font` 文件.

## 翻译

默认忠实转换主体、动作、数量、关系、服装和尺寸, 不凭空补外貌、镜头、天气或场景. 数值如“一米高”保留成明确英文短语. 画师串单独拼接, 不交给翻译模型重写.

可以设置独立的翻译模型, 完全替换 `translator_system_prompt`, 或追加自定义前缀. 翻译是单轮请求, 不携带群聊历史. 模型返回空文本、截断或拦截时停止生图, 不静默改用原文并收费. `--raw` 直接使用用户给出的 prompt.

自定义提示词用于调整翻译规则, 实际支持的内容以翻译服务为准.

## LLM 调用

`enable_llm_tool` 默认关闭. 开启并重载后注册两个独立工具:

- `nai4_generate_image(prompt, count?)`
- `nai5_generate_image(prompt, count?)`

在配置面板的 `llm_preset_nai4` 和 `llm_preset_nai5` 分别设置聊天生图预设名称或 ID. 留空使用对应模型的默认预设, 填写 `none` 不使用预设. LLM 不选择预设, 聊天调用也不读取指令切换的会话预设; `/预设` 和 `--preset` 仍只控制指令生图. 配置的预设不存在或属于另一模型时拒绝提交, 不替换画风.

工具仅在用户明确要求时调用, 保留原文, 不编造预设名, 不混用模型. 数量默认 1 张, 上限由 `batch_max_count` 控制. 调用立即提交后台任务并结束本轮工具回复, 不发送排队、翻译和生成中的提示. 图片单独发送到原会话; 若原对话仍有效, 整批完成后由 bot 按原人格自然接话一次. 切换会话后不会把旧图的完成回复带到新会话. 聊天调用失败不主动刷屏, 可用 `/nai任务` 查看状态和最近一次未提交原因. 关闭开关时不注册工具.

后续聊天只会读到 bot 自己调用工具发起的最近几次任务, 包括模型、原描述、实际提示词和发送状态. 指令生图和旧版没有来源标记的任务不会被算作 bot 的作品. 这些是任务记录, 不能代替对图像像素的视觉核验.

静默控制仅作用于当前消息, 不修改 AstrBot 全局设置或其他插件. 开启聊天生图时, 流式回复会缓冲到本轮完成后发送, 避免模型选择生图工具前先输出开场白. 不调用生图工具的正常文字回复仍会发送.

## 并发与费用

指令与聊天调用均在后台执行, 共享权限和并发限制. 默认同时生成 2 张, 总容量 10 个任务, 每人每会话最多 4 个待处理任务, 单次批量上限 4 张, 提交间隔为 0 秒. 可在设置中调整, 或开启仅管理员/用户白名单. 批量在容量不足时整体拒绝, 不会只接收部分图片; 每张图独立完成, 整批只接话一次. 指令提交时只确认一次张数, 翻译展示可单独开启; 聊天调用始终不展示翻译.

任务提交时固定模型、预设和参数, 后续修改不影响排队中的请求. 未提交的任务可在重载或重启后继续处理; 已生成但尚未发送的图片可继续投递. 对生成结果不明或发送结果不明的任务不自动重试, 避免重复计费、重复发送. 已保存图片可用 `/nai取图` 补发, 任务和图片默认保留 7 天, 新请求到来时清理过期记录.

Images 请求不自动传 seed, 避免部分中转把字符串随机种子改成数字导致 422. 重绘保留其他参数但使用新随机种子, 不提供固定 seed 复现保证. 图片发送失败不会自动重新生成. 命令和日志都不会回显密钥.

## 开发与测试

```bash
uv venv --python 3.12
uv pip install -r requirements.txt ruff
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/ruff check .
```

在包含 AstrBot 依赖的 Python 环境中运行同一测试命令, 会额外执行命令、工具和发送集成测试; 普通环境明确跳过这些集成测试.

参考 AstrBot 官方插件文档、BestNAI 工作流、gitee 生图的后台任务流程及 lifeschedule 的衣柜展示交互. 本插件独立实现.
